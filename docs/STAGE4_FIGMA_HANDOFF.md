# Stage 4 Figma-ready visual handoff

Scope: Exclusive Deals, free reservations and Merchant Staff redemption (Stage 4 only). Nothing here changes approved business logic. No Stage 5 material is included.
Generated by `figma-handoff/stage4/build-svgs.mjs` and `build-doc.mjs` from the real design tokens and the real EN/AR dictionaries, so frame copy equals implemented copy.

## 1. How to use this handoff

1. Open the master Figma file (do **not** overwrite `Figma Files/dealdash-figma`, the approved originals are untouched). Create a new page section "Stage 4" under each page named in section 3.
2. Drag the SVGs from `figma-handoff/stage4/<surface>/` onto the matching page. Frames import at design size (mobile 390 x 844, desktop 1440 x 900, boards 1200 wide). Text stays live text; set fonts to Plus Jakarta Sans (English) and IBM Plex Sans Arabic (Arabic).
3. Convert each imported frame to the DealDash components (K01-K05) when building the library; the SVGs show exactly which component is used where (column "Components").
4. Frames marked **-ar** are the RTL mirror of the English frame. QR codes, DealDash codes, times and numbers are left-to-right islands inside RTL frames. Arabic uses Western digits.
5. SVG fidelity: these are structured references (token colours, spacing, radii, real copy), not pixel clones. The QR graphic is illustrative; the app renders real QR codes. For pixel truth use `figma-handoff/stage4/reference-screenshots/` (captured from the working app, EN and AR).

Design tokens: `Figma Files/dealdash-figma/design-tokens.json` (navy #0F0C42, purple #5B1AFC, lilac #EEE8FF, mint #1FBF8F, amber #F5A524, red #E93A52, bg #F8F9FD, line #E3E1F0, hot gradient #FF7A1A to #E93A52; radii chip 99, card 20, hero 24, sheet 26, input 14).

- **F04 Reservation expires → inventory returns → customer sees expired** (8 steps): `flows/F04-reservation-expires-inventory-returns-customer-s.svg`
- **F05 Last unit → one customer succeeds → second sees sold out** (8 steps): `flows/F05-last-unit-one-customer-succeeds-second-sees-sold.svg`

1. F01: Merchant creates Exclusive Deal, configures branch inventory, submits, Admin approves (needs-changes loop returns to the builder).
2. F02: Customer discovers, opens detail, reserves for free, sees confirmation with QR/code/timer, visits the merchant.
3. F03: Staff SCAN, VALIDATE, REDEEM, with all failure results and the connectivity-retry path.
4. F04: Reservation expires, unit returns to inventory, customer sees "Reservation not completed", optional reserve again, restriction after repeated no-shows.
5. F05: Last unit: one customer wins the atomic stock move, the second sees "out of stock" then "Sold out"; unit returns only if the first expires or cancels.

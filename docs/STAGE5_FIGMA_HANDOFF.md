## 1. How to use this handoff

1. Open the master Figma file (do **not** overwrite `Figma Files/dealdash-figma`; the approved originals are untouched). Create a "Stage 5" section under each page named in section 3.
2. Drag the SVGs from `figma-handoff/stage5/<surface>/` onto the matching page. Frames import at design size (mobile 390 x 844, desktop 1440 x 900, boards 1200 wide). Text stays live text; set fonts to Plus Jakarta Sans (English) and IBM Plex Sans Arabic (Arabic).
3. Convert imported frames to the DealDash components (VK01-VK05) when building the library; the "Components" column shows which component each frame uses.
4. Frames marked **-ar** are the RTL mirror of the English frame. QR codes, DealDash codes, references, times and amounts are left-to-right islands inside RTL frames. Arabic uses Western digits. Mixed Arabic/Latin lines carry per-line bidi direction so dates and amounts read correctly.
5. SVG fidelity: structured references (token colours, spacing, radii, real copy), not pixel clones. The QR graphic is illustrative; the app renders real QR codes. For pixel truth use `figma-handoff/stage5/reference-screenshots/` (captured from the working app, English and Arabic, 57 images).
6. Frame IDs: **VC** customer, **VM** merchant, **VS** staff, **VA** admin, **VK** components, **VF** flows (the Stage 4 handoff uses C / M / T / A / K / F, so IDs never collide).

Design tokens: `Figma Files/dealdash-figma/design-tokens.json` (navy #0F0C42, purple #5B1AFC, lilac #EEE8FF, mint #1FBF8F, amber #F5A524, red #E93A52, bg #F8F9FD, line #E3E1F0; radii chip 99, card 20, hero 24, sheet 26, input 14).

### 8.3 Payment-state and refund consistency
- Order, payment and instance statuses use one vocabulary on every surface (VK05). Customer sees plain-language states; Admin sees the technical statuses.
- A voucher exists only after PAID; PENDING never shows a voucher link; FAILED shows attempts left; late success after cancel or expiry is refunded automatically and never issued (VF05).
- Refund path: REQUESTED, UNDER_REVIEW (voucher usable), APPROVED / PROCESSING (voucher blocked, "Refund in progress"), REFUNDED, REJECTED (admin reason shown to the customer), FAILED (customer sees calm "we are finishing your refund"; Admin can retry).
- A redeemed voucher cannot take the normal refund; Admin reverses the redemption first (VA17).
